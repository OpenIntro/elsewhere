# Elsewhere — Architecture

Browser-based persistent multiplayer isometric social world. npm-workspaces monorepo, TypeScript strict everywhere.

```
shared/   pure TS contracts + logic (no DOM, no Node). Imported by client AND server.
server/   Node: Express + Colyseus 0.18. One port serves client build, REST, websocket.
client/   Vite + React 19 + three + @react-three/fiber 9 + drei 10 + zustand 5.
scripts/  e2e/smoke/integration/load scripts (Playwright for browser ones), see README "Testing"
docs/     this file
```

The other browser / protocol scripts (`e2e-player`, `e2e-ui`, `server-integration`, screenshots, load) are listed with their flags in README "Testing".

`@elsewhere/shared` exports a custom `source` condition → `src/*.ts`. Vite, vitest and `tsx` (dev) resolve it, so dev/test never need a shared build. `tsc` for the server (and `node` in production) use `dist/` — that is why `build`/`typecheck` build shared first.

## Contracts (shared/src)

- **`math.ts`** — coordinates: X/Z ground, Y up, **+X east, +Z south**, yaw radians about +Y, `forward(yaw) = (sin yaw, cos yaw)` (three.js `rotation.y`). `rotateOffset(local, yaw)` maps object-local → world.
- **`config.ts`** — every tunable: speeds, radius, send/tick/patch rates, interpolation delay, chat radius/length, interaction radius/cooldowns, rate limits (token buckets), day length, Collective Reality thresholds, gazette cadence. Never hard-code duplicates.
- **`protocol.ts`** — `ROOM_NAME`, `C2S`/`S2C` message names with payload maps (`C2SPayloads`, `S2CPayloads`), synced-state shapes (`PlayerStateView`, `ObjectStateView`, `WorldStateView`), `JoinOptions`, REST paths (`API`) and request/response types, `ErrorCode`, enums (anims, emotes, reactions, chat channels, report reasons). All payloads JSON; server sanitizes user strings.
- **`appearance.ts`** — `Appearance` (ids only), option catalogs (`APPEARANCE_CATALOG`, `ACCESSORY_CATALOG`, warm muted palettes), `sanitizeAppearance`, `randomAppearance(seed?)`, `parseAppearanceJson`, `validateDisplayName`, `randomDisplayName`.
- **`clock.ts`** — `worldTimeAt(now, {epochMs, dayLengthMs})` → day, 0..1 `timeOfDay`, hours, `phase` (`morning | midday | golden_hour | dusk | night`), `phaseProgress`; `sunAngles`, `daylight`, `lightsShouldBeOn`. Server persists the epoch; clients add `clock.offsetMs` (from `welcome.serverTime`) via `serverNow()`.
- **`collision.ts`** — `resolveMovement(from, to, radius)` (sub-stepped, slides along colliders and shores, never ends overlapping), `isWalkable`, `collidesAt`, `findNearestWalkable`, `createCollisionWorld` (tests). Used by client prediction **and** server validation.
- **`memory.ts`** — `WorldEvent` (attributed, `significance` 0–3), `NewWorldEvent`, `GazetteIssue/Article` (articles carry `eventIds` + `templateId`), `PersistentWorldState`.
- **`world/interiors.ts`** — walk-in buildings (see "Interiors" below).
- **`world/`** — `terrainHeight(x,z)` / `groundHeight` / `isGroundWalkable` / `shoreRadius` / `islandOutline` (organic ~120×127 island, hills, Town Hall rise, promontory under The Unknown, creek through the Woods), `LOCATIONS` (9, with ambience keys), `PATHS` (winding polylines) and `DECKS` (dock + Mossy Bridge; walkable over water), `BUILDINGS` (front = local +Z, door centred on it), `INTERACTABLES` (89 entries, discriminated union by `kind`), `structures.ts` (`FOUNTAIN`, `PORTAL_ARCH` + `archPillars`, `STANDING_STONES`, `PROPS` incl. café tables), `TREES`/`ROCKS`/`BUSHES` (seeded, deterministic), `COLLIDERS` (derived from all of the above — never edit by hand), `SPAWN_POINTS`, `ITEMS`, `DISCOVERIES`.

Key data conventions:
- Seat ref in `PlayerStateView.seat`: `"<interactableId>#<seatIndex>"` (`seatRef`, `parseSeatRef`, `getSeat`). Seated character root = `seat.position` at `groundHeight + seat.height`, facing `seat.yaw`; standing up → `seat.exit`.
- `ObjectStateView` semantics per kind are documented on the interface (seat bitmask, door open, light on, bell ring count, pickup holder, fountain stage, portal awake, rune lit). Only `synced: true` interactables have entries.
- `PlayerStateView.appearance` is a JSON string (schema stays flat); parse with `parseAppearanceJson`.

## Interiors (walk-in buildings)

Interiors live in the same world space and room as everything else: no scene switch, no teleport. A building with `enterable: true` (`world/buildings.ts`: Café, General Store, Town Hall, Workshop, House 1, House 2, Boathouse; houses 3–5 are closed with `futureHome: true`) is a hollow shell: `colliders.ts` emits its walls (`source: 'wall'`, `WALL_THICKNESS` 0.28 m, a gap of `doorWidth` in the front face) and its furniture (`source: 'furniture'`) instead of one box, so client prediction, server validation and both pathfinders (client NavGrid A*, server-integration walker) see the same rooms. `groundHeight` returns the interior floor (`floorY` = base terrain + `floorLift`), a linear doorstep ramp in front of the door and low platforms (café stage, hall dais); `terrain.ts` levels the ground under walk-in buildings. `locationAt` returns the building's location anywhere inside it. Server: `WorldRoom.handleInteract` additionally requires `sameSpace(player, target)` (no using indoor things from outside a wall; doors work from both sides), and a reconnect hint never moves a saved position to the other side of a wall.

`shared/src/world/interiors.ts` API (for activities and other systems):

```ts
INTERIORS: readonly Interior[]           // one per enterable building; getInterior(id)
interface Interior {
  id; buildingId; name; locationId; purpose: 'cafe'|'store'|'hall'|'workshop'|'home'|'boathouse';
  floor: 'wood'|'stone';
  footprint: RectZone; inner: RectZone;  // RectZone = { center: Vec2, halfWidth, halfDepth, yaw }
  floorY; baseY; wallThickness; wallHeight;
  doors: InteriorDoor[];                 // { id (door interactable), position (opening centre), yaw (outward), width, apron: RectZone, inside: Vec2, outside: Vec2 }
  rooms: InteriorRoom[];                 // { id, name, bounds: RectZone } (open-plan zones)
  anchors: Record<string, InteriorAnchor>; // { name, position (walkable standing spot), yaw (facing the thing), y (floor) }
  furniture: FurniturePiece[];           // { id, kind, position, yaw, local, localYaw, shape|null, height, variant }
  platforms: InteriorPlatform[];         // { id, zone, height }
  seatIds: string[];                     // indoor chair/bench interactables (INTERIOR_SEATS → interactables.ts)
  lights: InteriorLight[];               // ceiling lamps (position, y above floor, colour)
}
interiorAnchor(interiorId, name) // throws on unknown names
interiorAt(p, margin?) / spaceAt(p) / sameSpace(a, b, isDoor?) / zoneContains(zone, p, margin?) / zoneLocal / zoneCorners
FURNITURE, INTERIOR_SEATS, wallSegments(building), floorHeightAt(...), rampLength(b), rampHalfWidth(b)
PROTECTED_ZONES: readonly ProtectedZone[] // every building footprint ('building') + the apron in front of each door ('door_apron', DOOR_APRON_DEPTH 3.2 m deep, door width + 2·1.1 m wide)
protectedZoneAt(p, margin?) // first zone containing p, or null — player building must refuse placement there
```

## Player building

Rulebook: `shared/src/building.ts` (pure; the client preview and the server run the same code).

```ts
PIECES / PIECE_KINDS / PIECE_CATEGORIES   // catalog as data: footprint w×d, height, layer, solid, structural, colliders, levels, snap, variants (muted colours)
validatePlacement(req, ctx) → { ok, kind, variant, x, z, rot, level, y } | { ok: false, reason, label? }
buildableAt(p) / isBuildable(p)          // THE protected-zone predicate: PROTECTED_ZONES (interiors.ts, +1 m) + paths, square, interactables, spawns, landmarks, decks, water, off-island
supportsOf / directDependents / cascadeRemoval / autoLevel / snapToGrid / footprint / pieceColliders / walkSurfaceAt
PieceIndex                               // spatial hash (4 m cells) + per-owner counts, used by server and client
refusalText(reason, label)               // the short human text shown next to the ghost
```

Round 2 additions to the rulebook: `PieceDef` flags `param: 'roof'` (house roof: `RoofParams { w, d, style: 'gable'|'hip', pitch: 0|1 }`, stored as compact JSON in `PieceLike.params` / `build_pieces.params`; `footprintOf(p)` is the footprint of any piece incl. parametric size and wall mounts; `parseRoofParams`, `roofParamsString`, `roofRise`, `roofEdgesSupported` (≥ 3 edges at least half walled), `detectRoofSpan` / `roofSpanFromCorners` / `roofParamsFor` for the roof tool), `mount: MountSpec` (wall mounts stored at the wall's centre with rot = the face; `mountWall`, `mountCentre`, height bands clash per face), `top` / `surface` (table-top things stand on surface pieces; `y` = the surface's height), `seats: PieceSeatSpec[]` (`pieceSeat`, `pieceSeatInteractable` → a regular `SeatInteractable` with id `bp:<pieceId>`), `legacy` (old roof tiles: still validated, loaded and rendered; hidden from the palette). Nature: `clearableNature()` (bushes + rocks ≤ `CONFIG.building.clear.maxRockRadius` on buildable land), `natureItem`, `validateClear`, `natureBlocking` (a placement blocked by an uncleared clearable plant is refused with reason `nature` + `natureId`), `canRegrow`. UI helpers kept here so they are unit-tested: `stackOnto`, `nextInRun`, `isWallKind`. Shared collision gained `CollisionWorld.disabled` (static collider ids switched off — cleared rocks — skipped by every query); `world/interactables.ts` gained `registerInteractableResolver` so `getInteractable` / `getSeat` resolve `bp:` seats on both sides.

Rules: grid 0.5 m (`CONFIG.building.grid`), quarter turns, storey `CONFIG.building.storeyHeight`, levels 0..`maxLevel`. Same-level pieces clash by layer (`base` floors/steps, `surface` rugs, `solid` walls/furniture, `roof`, `gable`); slim pieces (walls, fences, pillars) may share corners and T-joints. Upper slabs/roofs rest on structural pieces of the storey below, walls on walls below or on an upper floor, upstairs furniture on an upper floor; supports must be the builder's own pieces. Only level-0 `solid` pieces get colliders (doorways/gates: two posts).

Server (`server/src/building/`): `createBuilding({ persistence, memory, moderation, worldId, options, collision })` — `RoomHooks` service registered in `services.ts`. Pieces live in a `PieceIndex` + the shared `CollisionWorld.dynamic` layer (so `WorldRoom.handleMove`'s `resolveMovement` treats them like any wall) and in table `build_pieces` (migration 3: `world_id`, `id`, kind, variant, `x2`/`z2` integer half-metres, rot, level, y, owner id + name, text, created_at; PK `(world_id, id)`). `place` order: enabled → per-profile rate limit (`RateLimiter`, keyed by profile so reconnects don't reset it) → ban/build_ban → world/player caps → sign text (`sanitizeText`, length, chat mute, `filterText`) → `validatePlacement` with the requester's server position and every player position of every room of the world → block relations near the spot → re-validate (the async checks may interleave) → insert → broadcast. `remove`: owner only, refused while other pieces rest on it. Admin: `adminRemove(ids)` (cascades), `adminRemoveProfile`. `unstuck` teleports to a Town Square spawn (`C2S.unstuck`, rate limit `unstuck`, frees a seat first). Memory: `first_build` (per profile, `builders` set), `milestone` `build_pieces` at `CONFIG.building.milestones` (persisted counter `build:placedTotal`), `structure_roofed` (a roof over ≥ 4 of your walls incl. a doorway; once per structure); Gazette templates `first_build`, `structure_roofed`, `build_pieces`.

Round 2 server: `clear` (C2S.buildClear: validateClear with the requester's position, rate limit, ban, `clearDaily` per profile per 24 h; row in `nature_cleared` (migration 5: world_id, nature_id, profile_id/name, cleared_at); `collision.disabled` for rocks; broadcast `S2C.natureCleared`), `regrow` (from the room tick every 30 s: rows older than `regrowMs` whose spot passes `canRegrow` → deleted, `S2C.natureRestored {by: 'regrow'}`), `adminRestoreNature` (by ids or profile; `by: 'admin'`), `editText` (C2S.buildEditText: owner only, same moderation as placing; `S2C.buildUpdated`), `interact` (built seats: `WorldRoom.handleInteract` routes `bp:` ids here after the usual range / same-space checks; occupancy = players whose synced `seat` points at the piece; standing up uses the existing `interactions.stand` → `freeSeat`, which now finds the seat's exit through the resolver). Removing an occupied seat is refused; `adminRemove` stands sitters up first. `building_named` memory event (+ Gazette template) when a name sign goes on a house with ≥ 4 walls incl. a doorway and a roof, once per sign. The first snapshot chunk carries `cleared: string[]`; `PieceWire` gained an optional 11th field (params).

Round 2 client: `actions.ts` aiming (stack onto the upper part of a wall under the cursor with `extend` highlight; storey lock `lockLevel` (PgUp/PgDn, ▲▼); run continuation after each confirmed placement (`afterPlaced`, Next / N); house-roof tool with span detection or two corners; wall mounts onto the face under the cursor; table tops onto the surface under the cursor; picking looks through pieces dissolved for the local player); `sync.ts` (cleared set → `collision.disabled`, `refreshNavRect`, `world/natureMask.ts` (Nature registers each bush / rock instance slot; cleared ones get a zero matrix), `S2C.buildUpdated`, seat resolver + `player/extraInteractables.ts` source for targeting and click picking); `meshes2.ts` (house roof from the town's own `roof` / `gableEnds` / `pavilionRoof` kit, chimney, name signs, furnishings — triangle table in README); `BuildLayer.tsx` (params-keyed instancing groups, name-board lettering as canvas textures with night emission, clock hands from the world clock, light pieces' halos / point lights via `GLOW_AT`, wall-extend highlight, clear ring); `BuildUi.tsx` (tabs + search, roof options, storey control, Next, Clear tool, nature card, Edit words, `NamePrompt`).

**Chunked instancing + frame meter (cycle 02):** a template's instanced group (kind + style + upper flag + roof params) whose pieces add up to `BUILD_SPLIT_MIN_TRIS` (8,000) triangles is split by `BUILD_CHUNK_M` (48 m) square cells from each piece's centre (`groupKey` / pure `planRegroup` in `BuildLayer.tsx`; a piece is in exactly one group, its fade / cut slot carried through regrouping). Each group's bounding sphere comes from `fitGroupSphere` (box-centred, order-independent; three's own grows per instance), recomputed on every rebuild, so three's frustum culling skips cells out of the camera and the shadow box; picking, `aFade` / `aCut`, signs and halos are per piece and unchanged. Debug: `buildRender.visible` (calls / triangles of meshes in the camera frustum, pieces in view) and `buildRender.passes` (the layer's own calls per pass, from `onBeforeRender` / `onBeforeShadow`). Frame meter: `client/src/game/perf.ts` `FrameRing` (600 frames; the meter reads the newest 300), fed from BuildLayer's frame loop with the frame interval and `gl.info.render`; `snapshot().frame` (registered on the first frame, superset of the older section) and Settings → Display → Performance. Baseline: `scripts/perf-baseline.mjs` (`npm run perf:baseline`, dev client; README "Rendering cost").

**Sync (why not the schema):** pieces are not in the Colyseus state. A schema map of a few thousand entries would be part of every full-state encode for each joiner and of the reflection/patch bookkeeping every tick, and pieces never change after placement. Instead: on join (and on `C2S.buildSync`, which the client sends after an automatic reconnection) the server sends `S2C.buildSnapshot` chunks (`CONFIG.building.snapshotChunk` = 500 rows of compact tuples + an owner table; cached until the next change), then only deltas: `S2C.buildPlaced` / `S2C.buildRemoved` to every room instance of the world, and `S2C.buildResult` (ok, or refusal + text) to the requester. 2,000 pieces ≈ 74 KB once per join; state patches are unchanged (README "Player building" has the measurements).

Client (`client/src/build/`): `sync.ts` (snapshot/deltas → `pieces.index`, the default collision world's dynamic layer — client prediction — and `refreshNavRect` on the click-to-move `NavGrid`; registers the read-only `build` debug section), `store.ts` (zustand UI state; pieces are module-level, not React state), `actions.ts` (enter/leave, aim = snap + `autoLevel`/`validatePlacement` for the green/red ghost, aiming at the top of your walls stacks, place/remove/undo/report/unstuck), `input.ts` (B, R, Enter, X, Ctrl+Z, Esc; pointer routing from `PlayerSystems`), `BuildLayer.tsx` (one `InstancedMesh` per kind + variant + material bucket, per-instance dithered fade attribute `aFade` for roofs/upper storeys near the player and tall walls between camera and player (≥ 0.995 = fully gone), per-instance hard-cut attribute `aCut` (0 = none, else 1000 + a world clip height; cut parts show their back faces as a dark cap — the piece materials are double-sided but discard uncut back faces first), a fade- and cut-aware shadow depth material, the built-interior cutaway (each fade tick: shared `trackEnclosure` → `builtCutaway.ts` `planCutaway` for the camera yaw → camera-facing walls eased down to 0.95 m stubs, their mounts cut away, everything above the storey faded to gone, sign text / clock hands / lamp glass / halos of hidden pieces hidden; per viewer, no extra draw calls), sign text canvas textures, lamp halos + two nearest point lights by the world clock, ghost + selection), `meshes.ts` (code-built templates in the world's clay/painted-wood style, triangle-budgeted), `BuildUi.tsx` + `build.css` (nav button, dock with palette thumbnails rendered from the real templates, styles, sign text, Rotate/Remove/Undo/Place/Done, status line, selection card), `surface.ts` (feet on floor boards/steps). Debug: `snapshot().build` (synced, mode, ghost, counts, pieces list), `snapshot().buildRender` (draw calls, triangles) and `snapshot().builtCutaway` (`active, kind, rect, storey, cutIds, hiddenIds, toggles, settled`, per-piece `cut` / `fade` amounts); queries `pickPiece(x, y)` (what build picking hits) and `rayPieces(x, y)` (everything a screen ray passes through, ignoring fades and cuts). `picking.ts` looks through faded pieces and through the parts of a piece above its cut, and ignores back faces.

Built interiors (`shared/src/buildEnclosure.ts`, pure, render-only): `enclosureAt(index, p)` → the room of built pieces containing `p` or null — (a) roofed: the union of the roofs / roof tiles / upper floor tiles over `p`, grown across overlapping covers and across touching ones that no wall of the storey separates (an L house's two roofs → one room; two huts sharing a wall → two), or (b) walled: the rectangle from the nearest wall line on each side of `p` (≥ 3 sides at least 70% walled; an open side is closed where the side walls end); at most 12 x 12 m; any owner's pieces. Result: `rect`, `parts` (rects whose union is the room), `storey`, `walls` (wall-type pieces of that storey on the outline ±0.5 m, with outward normals), `inner` (partitions), `above` (every piece above the storey inside it, incl. mounts). `enclosureDepth`, `enclosureHysteresis` (enter ≥ 0.3 m inside, leave ≥ 0.6 m outside), `trackEnclosure(index, p, prev)` (the per-viewer tracker; re-finds the room from the last point well inside while you stand on the threshold). Client `builtCutaway.ts`: `cameraFacingWalls(e, yaw, index?, player?)` (outline walls whose outward normal points at the camera, cos > 0.26, + partitions between you and the camera), `mountsOn(index, walls)`, `planCutaway(index, e, yaw, player)` → `{ cut, hidden }`.


## Homes

Rule (`shared/src/homes.ts`, pure): `checkHouse(ownerPieces, pieceId, { prefer? })` → `{ ok: true, house: { rect, parts, doorPieceId, roofPieceIds, wallPieceIds, signPieceId?, name } } | { ok: false, reason: HomeRefusal }` (`houseFor` = the house or null; `HOME_REFUSAL_TEXT` the player-facing reasons). It builds a `PieceIndex` from the selected piece's **owner's pieces only** and runs `enclosureAt` at a probe inside that piece's house (0.6 m along each normal of a wall-type piece — mounts use their wall —, the footprint centre of anything else; the piece must belong to the room found). Qualifies: `roofed` room, one of the owner's roofs (`layer: 'roof'`: house roof or legacy tile) in `above`, ≥ 4 outline walls of kind wall / wall_window / doorway, ≥ 1 doorway. Door: the selected doorway, else the lowest-id outline doorway. Name: the owner's `name_board` > `name_hanging` > `name_plaque` on an outline wall whose mount offset points along that wall's outward normal. `prefer` breaks the tie for a doorway shared by two of the owner's rooms (the server passes the stored room).

Server (`server/src/homes/`): `createHomes({ persistence, memory, moderation, building, worldId })` — `RoomHooks` service registered in `services.ts` after building (`linkModeration(moderation, homes)` wraps `block` / `unblock` / `sanction` / `revokeSanction` so relation and sanction changes reach it at once). Table `homes` (migration 6: `world_id`, `profile_id`, `door_piece_id NOT NULL`, `show_on_map` default false, `created_at`; PK `(world_id, profile_id)`, UNIQUE `(world_id, door_piece_id)`; no rect — `repository.ts`). Building gained two listeners (`building.onChange({ added, removed, updated })` after every committed place / remove / text edit / admin removal incl. cascades and `adminRemoveProfile`, and `building.onSnapshotSent(ctx, sid)` after every snapshot: join and `C2S.buildSync`). Messages (WorldRoom routes them, rate limit `CONFIG.rateLimits.home` per profile inside the service): `C2S.homeSet {pieceId}` (piece exists → owner → not banned / build-banned → `checkHouse` over the owner's pieces near it → upsert; a second set moves the home and keeps the pin choice), `C2S.homeClear`, `C2S.homePin {on: boolean}`; each answered with `S2C.homeResult { action, ok, reason?, text?, doorPieceId? }`. Upkeep: a change of the owner's pieces touching the home's rect + 1 m (or the door itself) re-runs `checkHouse` (prefer = the stored rect); failure → home deleted, `S2C.homeChanged {profileId, cleared: true}` everywhere, a `home_cleared` notice to the owner's sessions; a changed room / name → `S2C.homeChanged {home}`. Load (first `onRoomCreate`, and `services.ts` at boot): rows whose door piece is gone or no longer qualifies are dropped. Writes are serialized (a clear and an immediate re-set land in order).

Sync and filtering: `S2C.homes {homes: HomeWire[]}` right after the build snapshot, `S2C.homeChanged` to every room instance; `HomeWire = { profileId, ownerName, doorPieceId, name, rect, pinned }` with `pinned` computed **per recipient**: the owner sees their own choice; anyone else sees false when the owner is banned / build-banned (cache refreshed on sanction create / revoke and every 30 s for expiries) or when either has blocked the other (moderation's live cache for the recipient, the owner's own block list cached from `relations` so it holds while the owner is offline). Memory: `home_made` (actors: the owner; data: the name; **no location, no object id**), once per profile per door (world set `homes_made`); Gazette template `home_made` ("{name} made {title} their home").

Client: `client/src/build/homes.ts` (zustand store fed by `sync.ts`: `applyHomes` / `applyHomeChanged` / `applyHomeResult`; `homeActions.set/clear/pin`; `houseOfPiece` runs the shared rule on the local pieces only to offer the button; `insideCount(home)` counts `net.state.players` inside the room; read-only `snapshot().homes { synced, pending, result, mine, homes[{…, inside}], stats }`). `BuildUi.tsx`: `HomeControls` on the selection card of your own piece (`home-make` / `home-is-yours` + `home-stop` / `home-refusal`); `NamePrompt` shows the nearest home within 4 m of its outline first ("Fern Cottage · Ivy’s home · N inside", N ≥ 1 only). `SimplePanels.tsx` `HomePanel`; `MapPanel.tsx` pins (`map-home-<profileId>`, label "Fern Cottage · Ivy" / "Ivy’s home"). No new render objects.

## Server

`index.ts` → `initServices()` (composition root `services.ts`) → `defineServer({ rooms: { world: WorldRoom }, express })`. Express app (inside Colyseus' HTTP server) mounts `/api/*`, static `client/dist`, SPA fallback. Colyseus matchmaking (`/matchmake/*`) and websockets share the port.

`WorldRoom` (rooms/WorldRoom.ts):
- `onAuth`: protocol version check; token → profile (`auth.verify`), banned profiles refused, else a new guest profile.
- `onJoin`: resume at the profile's last position (else spawn ring), `PlayerState`, `onPlayerPreJoin` hooks (moderation caches), `S2C.welcome`, `onPlayerJoin` hooks; first-visit/return memory + collective signals run 1.5 s later (`JOIN_SETTLE_MS`). `onDrop` → `allowReconnection(grace)` (rejection caught; kicked sessions get none). `onLeave` → hooks, save profile (position, stats), remove. Profiles autosave every 60 s and on dispose; moved players' positions are flushed every 2 s (`POSITION_SAVE_MS`, one UPDATE each) so a hard kill loses ≤ 2 s of movement. On rejoin the SAVED position wins; `JoinOptions.resume` is only used if it is walkable and within 3 m of it (`resumePosition`).
- State (`rooms/schema.ts`, Colyseus schema 5 `schema()` API — no decorators): `players` map, `objects` map seeded from `SYNCED_INTERACTABLES`, `clockEpoch`, `dayLengthMs`. Compile-time checks keep it aligned with the shared `*View` interfaces. **Append new fields at the end.**
- Every C2S message goes through `on(type, rateLimitAction, handler)`: player must exist, token-bucket rate limit (`S2C.rateLimited` on reject; rejections feed moderation's auto-mute), non-object payloads coerced to `{}`, errors → `S2C.error`. Chat/whisper/typing/stand/mail_read rate-limit inside their services.
- Services get a `RoomContext` (send, broadcast with filter, notice/error, timers, teleport, `worldTime`, `getProfile`/`saveProfile`, `sessionForProfile`, `kick`, state access) and may implement `RoomHooks` (`onRoomCreate`, `onPlayerPreJoin`, `onPlayerJoin/Leave`, `tick`, `onRoomDispose`). Register hook-bearing services in `services.ts`. Live room contexts are in `roomRegistry` (admin tools).
- Scoping: services are per world (`DEFAULT_WORLD_ID = 'default'`); transient gameplay state (lit runes, bell rings and chorus cooldown, door/respawn timers, per-player cooldowns, light overrides, location tracking, chat history) is keyed by `ctx.roomId`, so a second room instance never shares it. Persistent world facts/sets/object states are keyed by `world_id` in storage (`persistence.forWorld(id)`).

Seams (all implemented; each file's header documents its rules):
- `persistence/` — Postgres SQL over two drivers (`db.ts`): embedded PGlite in `$DATA_DIR/pglite` by default, `pg` when `DATABASE_URL` is set. Ordered idempotent migrations in `migrations.ts` (run at boot, tracked in `schema_migrations`: #1 base tables, #2 `world_id` keys, #3 `build_pieces`, #4 `activity_notes` + `poll_votes`, #5 `nature_cleared` + roof params, #6 `homes`). Repositories: profiles, sessions, events, gazette, worldState/`forWorld`, mail, reports, relations (block/mute), sanctions. `flush()`/`close()` await in-flight writes.
- `auth/` — opaque HMAC-signed tokens (`es1.…`, sha256 stored, survive restart), guest sessions resume by token, register/login (scrypt), guest→account upgrade keeping the profile, logout revokes, per-username lockout; optional Supabase JWT (`SUPABASE_JWT_SECRET` HS256 / `SUPABASE_URL` JWKS).
- `moderation/` — block/mute (persisted, server-enforced; C2S payloads take `target` sessionId or `profileId`, so offline players can be unblocked/unmuted; lists with names in `welcome.blockedProfiles/mutedProfiles` and `GET /api/profile/relations`), reports with chat evidence, sanctions (`chat_mute`/`ban`, timed or permanent), auto chat-mute on repeated rate-limit abuse, `text.ts` sanitizing + profanity mask.
- `chat/` — proximity (radius), global (history per room), whisper, mentions, typing; mute/rate/length/duplicate checks.
- `interactions/` — every interactable kind server-authoritatively (seats, doors, lights, bell, pickups, mail, hidden discoveries, fountain/rune/portal via collective, signs/inspect/newsstand/archive).
- `collective/` — data-driven rules engine (`rules.ts`: fountain stages, popular places, night wanderers, resident milestones; thresholds from `CONFIG.collective` + env), the portal and bell secrets, gatherings, persisted clock epoch.
- `memory/` — attributed, time-sortable World Memory; `announce` broadcasts `S2C.worldEvent`.
- `gazette/` — issues compiled on a cadence from real events via `templates.ts` (no events → no issue); persisted cursor. Young world: the first issue is compiled `earlyIssueDelayMs` after `earlyIssueSignificantEvents` significant events.
- `activities/` — building activities and keepers (see "Building activities").
- `http/api.ts` (+ `admin.ts`) — REST incl. `GET /api/world` and admin tools under `/api/admin/*` (Bearer `ADMIN_TOKEN`; 404 when unset; incl. `/api/admin/notes`); per-IP rate limits.

Server env: see "Running" above (the full list, parsed in `server/src/env.ts`) and README "Environment variables" (defaults and meaning).

Server checks: `npx vitest run server`; `npx tsx --conditions=source scripts/server-integration.mjs [url] [--save f | --verify-restart f | --position-save f | --position-verify f]` against a running server (header lists the env it expects; it refuses to run if its world-layout fingerprint differs from `GET /api/world`'s `worldDataHash`).

## Client

- **Stores** (`state/`): `useGameStore` (connection, session/profile, roster `players` *without positions*, `objects`, `clock`, collective `world`, block/mute lists), `useUiStore` (phase, open `panel`, interaction `prompt`, notifications, `textInputFocused`, chat log), `useSettingsStore` (master + music/sfx/ambience volumes, graphics, controls; persisted to localStorage via try/catch storage).
- **Per-frame data never goes through React state**: `state/runtime.ts` holds `runtime.localPlayer` (predicted pose) and `runtime.remotes` (snapshot buffers). Read them in `useFrame`.
- **net/**: `net.connect({name, appearance})` (REST guest session → `joinOrCreate`; idempotent), `net.send(C2S.x, payload)` (typed), `net.on(S2C.x, handler)` (typed bus; every S2C type is registered), `rest.*` typed REST, `sampleRemote(id, out)` interpolation (render `interpolationDelayMs` in the past), `installDebugHook` → `window.__ELSEWHERE__.snapshot()` (read-only; used by the smoke/e2e tests — keep it; the `world` section exposes synced fountain/portal/rune/bell objects and the local profile's name + appearance). `CharacterPreview` writes its rendered yaw to `data-yaw` on `[data-testid=character-preview]` for the drag-to-rotate check.
- **player/**: `LocalPlayer` (prediction with shared `resolveMovement`, sends `move` at `sendRateHz`, `stand` when moving while seated), `CameraRig` (orthographic iso, offset (30,30,30)), `input.ts` (`sampleInput`, `screenToWorld`, `setTouchMove`, `pressInteract`, `onInteractPressed`), `interaction.ts` (nearest interactable → `ui.prompt`, E → `C2S.interact`, results → panels).
- **Camera turning (input model).** The view has four settled orientations, `yaw = BASE_YAW + rotation·90°` (`player/camera.ts`). Discrete turns — the HUD turn buttons, `[` / `]` (always, also in build mode) and `Q` / `R` (outside build mode only: while building the build key interceptor takes `R` to turn the piece) — call `cameraControls.rotateLeft/Right()`, an eased tween (`ROTATE_MS` 480 ms per 90°). Continuous turns — right / middle mouse drag (`DRAG_RAD_PER_PX`, 90° per 260 px) and a two-finger twist on touch — feed `dragRotate()`, which sets `cameraRuntime.dragYaw` so the yaw follows the gesture directly; on release `endDragRotate()` eases to the nearest 90° (`nearestRotation`, a shorter tween for a small settle). A two-finger gesture is classified once (`classifyTwoFinger`: twist vs pinch, from the dominant total angle / log-scale) and then only that one acts, so a pinch zooms without turning. WASD / joystick directions read the live `cameraRuntime.yaw` (`screenToWorldDir`) and taps / clicks / build aiming raycast through the live camera, so input stays screen-relative mid-turn.
- **Camera focus shift (phones).** On phone layouts only (`PHONE_QUERY`: width ≤ 720 px, or landscape with height ≤ 500 px) the rig collects the rects of elements marked `data-camera-cover` (the collapsed landscape build strip / its palette, a `Sheet` in peek), takes the largest free rect they leave (`freeRectFor`; a cover leaving < 18% of the viewport is ignored) and eases `cameraRuntime.shift*` toward the offset of that rect's centre (`shiftForFree`). It applies the shift by moving the camera's look-at point (`lookAtForShift`), never with `setViewOffset` or a projection change, so the camera matrices themselves carry it: `screenToWorld` (tap-to-move), the build raycaster / ghost and `runtime.view` all agree, and the player is never moved. Desktop: no covers are read, the shift stays 0.
- **world/**: `<World />` — renders shared world data (incl. solid `FENCES`/`DECOR`) + lighting from the clock + synced object visuals. Quality profile (`world/env.ts` `QUALITY`) drives shadows/shadow-map size (it owns `gl.shadowMap.enabled` and recompiles on change), point-light budget, density and terrain resolution. `World` also sets the renderer's tone mapping (ACES, exposure 1) and caps the pixel ratio per quality via `setDpr` (1 / 1.5 / 2), overriding the Canvas `dpr`. Dev-only overrides: `?time=&fountain=&portal=&runes=&doors=&weather=&quality=&cam=&inside=` and `window.__ELSEWHERE_WORLD__` (info/bench/breakdown/coverage); screenshots via `scripts/world-screenshots.mjs`.
- **characters/**: `<Character appearance anim animSeq held highlighted castShadow />` renders at origin (feet y=0, facing +Z); parent group moves it. `<CharacterPreview appearance anim spin />` is its own Canvas.
- **ui/**: `Hud`, `Chat`, `Onboarding({onDone})`, `CustomizationScreen({initial,onSave,onCancel})`. `App` resumes a saved session or runs onboarding before `net.connect`; `?autojoin=1` (tests) joins at once as a random guest.
- **audio/**: `audio.unlock()`, `playSfx(SfxName, position?)`, `setAmbience(AmbienceKey|null)`, `playMusic(track)`, `setListener`, `gainFor(channel)`. Procedural only.

## Data flow

**Movement.** Input → `LocalPlayer` integrates speed × dt → `resolveMovement` (shared) → `runtime.localPlayer` (render immediately) → every 1/15 s `C2S.move {x,z,rot,anim,seq}` → `WorldRoom.handleMove`: drops stale seq; seated → `correction(seated)`; refills a per-player distance budget at `runSpeed × speedTolerance` (capped) and clamps the claimed move to it; `resolveMovement` from the last authoritative position; writes `PlayerState` (x, y=`groundHeight`, rot, anim, location). If the result differs from the claim by > `correctionThreshold` → `S2C.correction` → net snaps `runtime.localPlayer`. Patches (20 Hz) → client `onStateChange` pushes remote snapshots → `RemotePlayers` samples interpolated poses each frame.

**Chat.** UI → `C2S.chat {channel, text}` / `C2S.whisper {to, text}` → chat service: rate limit, `filterText`, length, `extractMentions`, block/mute filters, proximity filter via `ctx.broadcast(..., {filter})` → `S2C.chat ChatMessage` → ui chat log/bubbles; client hides muted/blocked profile ids too.

**Interaction.** Player targeting picks nearest interactable in range → prompt → `C2S.interact {id, action?}` → WorldRoom validates existence + range (+slack) + rate limit → `interactions.interact(ctx, sid, target, payload)` mutates `state.objects` / player, may `ctx.broadcast(S2C.objectEvent)`, records `memory`, signals `collective` → `S2C.interactResult {ok, error?, ui?}` to requester → panels. Object visuals update from `objects` state for everyone.

## Adding things

- New message: add name to `C2S`/`S2C` + payload type to the payload map in `shared/src/protocol.ts`; register in `WorldRoom.registerMessages` (pick a rate-limit action) or in a service; client sends via `net.send` / listens via `net.on` (automatically registered).
- New synced field: append to the schema in `server/src/rooms/schema.ts` **and** the `*View` interface; bridge it in `net/connection.ts` if UI needs it.
- New interactable: add to `INTERACTABLES` (collider derives automatically for solid kinds); run `npm test` — tests check reachability, seat exits, ids, locations.
